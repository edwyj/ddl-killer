# 为你的学校开发课表导出适配

DDL Killer 希望让大学生把上课、作业、考试和自己的计划放在一起。教务系统负责告诉你什么时候上课，导出适配负责把这些信息转换为 DDL Killer 能理解的课表，让课程成为安排其他事情时可以参考的固定时间。

欢迎有能力的同学在遵守学校规定的前提下，为自己的学校编写导出脚本、改进已有适配，或者把这套方式用于自己的校园工具。你不需要提供教务账号，也不需要公开个人课表。一个可以离线复现的虚构样本，比包含个人信息的完整页面更适合提交到仓库。

本教程说明当前源码的导入格式与适配流程。现有学校脚本提供具体实现参考，**不是可以替换域名就通用的脚本**。新学校仍需贡献者核实页面、校历、作息和使用规则。

## 先选合适的数据来源

优先检查学校是否提供官方的课表下载、日历订阅或导出接口。有的话，先在本地转换官方导出文件，可以减少对教务页面结构和登录状态的依赖。DDL Killer 当前导入的是下面的 JSON 格式；CSV、Excel、ICS 等文件需要先转换，不能直接当作 JSON 导入。

若学校允许在个人已登录页面运行辅助脚本，可以从本人可见的课表页面读取内容，或沿用该页面正常使用的本人课表查询请求。开发前确认适配适用的校区、培养类型和教务系统版本；同一个学校不同校区也可能完全不同。

请把范围限制在用户正常有权查看的本人课表。不要绕过验证码、登录、访问控制或学校限制；不要枚举学号、修改身份参数或查询他人信息。遇到限制时停止，并改用学校允许的导出方式或向学校咨询。

建议把脚本拆成四步：

```text
本人允许导出的数据 → 纯解析与归一化 → 校验并显示摘要 → 用户点击下载 schedule.json
```

让解析函数只接收文本或对象、返回普通对象；把网络、页面按钮和文件下载放在外层。这样没有教务账号、没有网络的维护者也能检查逻辑。

## 当前有哪些实现可参考

| 实现 | 可以参考的做法 | 适配新学校时必须重新确认 |
| --- | --- | --- |
| [山东大学脚本](../app/web/userscript/sdu-kebiao-export.user.js) | 解析 HTML 课表网格、逐周查询后聚合课程、下载 JSON | 当前匹配的是威海教务域名；学期、第 1 周日期、查询周数和作息含固定配置，不代表所有校区或新学期 |
| [哈工大（深圳）脚本](../app/web/userscript/hitsz-kebiao-export.user.js) | 解析整学期条目、展开单/双周、查询节次与校历、区分实验分组 | 接口路径、文本结构、校历可信度，以及作息获取失败时的处理 |
| [哈工深离线解析验证](../app/tool/hitsz_kebiao_export_test.mjs) | 使用虚构输入测试多行课名、实验课、周次、重复条目、日期和接口路径 | 你的学校应有自己的输入夹具与预期输出，不能只沿用其他学校样本 |

已有脚本中的兜底与历史配置需要逐项理解。例如，山东大学脚本当前查询至多 20 周并使用简化作息；哈工深脚本在学期日期获取失败时会警告并暂用本周周一。新适配不应静默沿用这些值；导出前应要求用户确认真实日期和时间，或停止并说明缺失的信息。

## JSON 数据格式

完整的虚构课表在 [timetable-demo.json](examples/timetable-demo.json)。包含同一课程的多个时段、单周课、双周课和不同周次换教室的示例，可以下载后在自己的测试账号中导入。示例的课程、教师、教室、学期与作息均为编造。

当前的核心读取位置是 [后端课程展开](../backend/src/schedule.js)、[客户端离线课程展开](../app/lib/offline_projection.dart) 和 [导入界面](../app/lib/screens/schedule_import_screen.dart)。以下是贡献者应遵循的格式；目前导入界面与 API 只做浅层检查，**成功导入并不代表每个日期、节次都正确**，需要完成后面的验证。

| 字段 | 类型与含义 | 适配要求 |
| --- | --- | --- |
| `semester_start` | `"YYYY-MM-DD"` | 第 1 教学周的周一。必须是真实有效的日期；不能用报到日、今天或第一门课的日期代替 |
| `semester` | 字符串，可选 | 学年学期说明，例如 `2026-2027-1`；不参与周次计算 |
| `period_to_block` | 对象，小节号 → 大节号 | 键为小节号字符串，值用正整数，如 `"1": 1, "2": 1` |
| `period_times` | 对象，大节号 → 起止时间 | 如 `"1": ["08:00", "09:35"]`；使用学校当地的 24 小时时钟 `HH:mm`，当前结构不带时区或跨午夜表达 |
| `courses` | 课程对象数组 | 固定上课时间的课程；同一门课的多个安排放在它的 `slots` 中 |
| `courses[].course_id` | 稳定字符串 | 优先使用不含学生身份的课程/教学班标识；缺失时可从稳定的课程与班级特征生成，不能用导出时间或随机数 |
| `courses[].name` | 非空字符串 | 用户能识别的课程名，保留区分课程所需的名称与分组 |
| `courses[].teacher` | 字符串，可省略或留空 | 当前是课程级字段；同课不同教师可明确合并展示，不要假装支持时段级教师 |
| `courses[].slots` | 时段对象数组 | 每个对象描述一个星期、一个大节、若干上课周与相应地点 |
| `slots[].weekday` | 整数 `1`…`7` | 周一为 `1`，周日为 `7`；不是 JavaScript 的周日 `0` |
| `slots[].weeks` | 正整数数组 | 从第 `1` 周起计数，去重并升序排列；奇偶周必须先展开 |
| `slots[].periods` | 正整数数组 | 小节号，去重并升序排列；一个时段中的小节必须属于同一个大节 |
| `slots[].room`、`group` | 字符串，可留空 | 地点与实验/教学分组；没有信息时不要编造 |
| `slots[].section` | 可选标识 | 现有脚本用于教学班或时段序号，不决定具体日期与时刻 |
| `time_note`、`week_source` | 字符串，可选 | 记录作息和周次的来源或已知局限，方便排查；不要假定应用会主动显示这些备注 |
| `no_fixed_time` | 数组，可选 | 现有导出脚本可用于保留无固定时刻的课程元信息；当前课程展开不会把它转成日历事件 |

`updated_at`、`type`、`attr` 等现有脚本附加字段可用于说明来源或课程属性，但不改变排课计算。不要把登录令牌、学号、联系方式或整段原始响应塞进额外字段。

### 周次与学期日期

先查学校校历或页面显示的“第 1 周”，确认这一周的周一。当前算法按 `semester_start` 起每 7 天递增一周，再匹配当天星期；它不会自动识别学校调休规则。跨年学期也使用完整年份，不能只拿学年字符串的前四位补所有月日。

常见写法应转换为：

| 学校原文 | `weeks` |
| --- | --- |
| `1-4周` | `[1, 2, 3, 4]` |
| `1-8周 单周` | `[1, 3, 5, 7]` |
| `2-8周 双周` | `[2, 4, 6, 8]` |
| `1-3,5,7-8周` | `[1, 2, 3, 5, 7, 8]` |

不要只保留“单”“双”文本，也不要只查看当前周。必须覆盖完整学期，尤其是只在后半学期开设的课程。逐周查询时按学校规则控制频率、限制总周数、避免并发轰击，显示进度并允许用户停止；失败周次不能当作“无课”静默跳过。

调休换日、临时停课和补课目前没有单独的例外字段。能确定具体日期时，可以据该日期换算 `weekday` 与 `weeks`，拆出相应时段，并从原安排删除被替换的那一周；不能确定时应列明待核对项目，不能猜测。日期转为周次后，仍须在日历上核对实际那一天。

### 节次与真实时刻

当前后端和离线客户端都只取 `periods[0]`，通过 `period_to_block` 找到一个大节，再使用 `period_times` 的起止时间。**不会遍历全部节次来计算跨度，也不会读取时段上的自定义 `start_time` 或 `end_time`。**

例如学校的第 1、2 小节组成 08:00–09:35 的一个大节，应输出：

```json
{
  "period_to_block": {"1": 1, "2": 1},
  "period_times": {"1": ["08:00", "09:35"]}
}
```

对应时段的 `periods` 为 `[1, 2]`。每个用到的小节都要能找到大节和时间；缺少映射可能产生 00:00 的课程，让日历和 AI 对空闲时间的判断失真。

若一门课连续跨第 1、2 大节，需要拆成两个时段，分别保留正确的星期、周次与教室。相同课程周一和周三上课，也要分别建时段。不同周次使用不同教室时拆开周次集合；不要把多个教室用斜杠合并后当成已经准确表达了换教室时间。

当前时间表是全课表共用的：同一个小节号只能映射到一个大节，一个大节只有一组固定起止时间。如果学校有仅上一小节、夏冬作息切换、不同日期同节次不同时间等情况，先核实是否能用一致的映射准确表达；无法表达时在贡献说明中明确列出，并与维护者讨论格式扩展。不要拿其他学校的作息补齐并宣称精确支持。

### 课程合并、重复与不完整数据

优先使用学校稳定的课程与教学班标识合并 `courses`。同名的不同课程或实验组不能只按名字合并。一个课程中的重复时段，可以按课程标识、星期、周次集合、节次、地点与分组去重；不要为了去重丢掉不同周次或地点。

保留空教室、空教师是可以的。缺少星期、周次或时间的记录不能默认成周一、第 1 周或第 1 节；应展示无法解析的条数和原因。可保留在明确的未排定课程列表中，但须说明它们还没有进入日历。

## 做一个可检查的导出过程

推荐先完成一门虚构课程的转换，再处理整学期。解析应限制输入长度和周次范围，遇到陌生结构返回明确错误。不要把“返回了 HTML 登录页”“网络失败”“权限不足”当作空课表继续导出。

导出前显示课程数量、时段数量、学期、第 1 周周一，以及是否有无法解析的记录。如果必须由用户补充校历或作息，先显示具体信息并确认，再生成文件；不能只写入一个警告字段后假定用户会看到。

在浏览器中，下载本地 JSON 不需要额外服务：

```js
// schedule 是完成归一化和校验的普通对象。
// 在用户主动点击导出按钮后执行。
const blob = new Blob([JSON.stringify(schedule, null, 2)], {
  type: 'application/json;charset=utf-8',
});
const url = URL.createObjectURL(blob);
const link = document.createElement('a');
link.href = url;
link.download = 'schedule.json';
document.body.appendChild(link);
link.click();
link.remove();
setTimeout(() => URL.revokeObjectURL(url), 5000);
```

使用 UTF-8，推荐不带 BOM。当前选择文件入口支持去除开头 BOM，但拖入和粘贴入口的处理不同，生成无 BOM 文件更稳妥。文件应不超过 1 MB。导入会替换当前账号已有课表；验证时使用自己的本地测试账号，保留旧文件。

### 脚本权限与隐私

新油猴脚本的 `@match` 尽量限定到实际教务域名和所需页面；不要匹配所有网站。能用普通页面脚本完成时使用 `@grant none`，需要其他权限时解释具体原因。iframe 宿主也应确定且可见，避免把按钮放在隐藏 frame 或重复注入。

只在用户点击后读取必要信息。若沿用已登录的同源查询，使用当前页面允许的请求，不读取、导出或上传 Cookie、密码、令牌，也不加第三方统计、远程脚本或遥测。账号密码由用户在学校页面正常输入，脚本不提供代登录、自动破解或凭据收集功能。

导出文件只保存在用户设备，由用户决定是否导入 DDL Killer。**“导出不外传”描述的是这一步；导入线上 DDL Killer 后，课表会发送给相应服务保存。**不要把整个流程描述成课表永不离开设备。给新脚本配置自动更新地址时，确认仓库归属、发布渠道和更新权限；不复制现有脚本的维护者署名或官方地址充当自己的。

报错只显示必要的状态、步骤和错误类型；不要把包含凭据的完整请求、响应或带个人参数的 URL 输出到日志、Issue 或截图。

## 离线验证，再到本人页面验收

先安装项目规定的 Node.js 24。在仓库根目录运行：

```sh
# 校验虚构样例，并调用实际后端函数核对日期、时刻、奇偶周与换教室。
node docs/examples/validate-timetable-demo.mjs

# 用同一工具检查自己生成的文件；路径按实际修改。
node docs/examples/validate-timetable-demo.mjs /path/to/schedule.json

# 现有哈工深解析回归；不访问教务系统。
node app/tool/hitsz_kebiao_export_test.mjs
```

Windows 路径含空格时加双引号。示例校验器使用内存 SQLite，不读取真实用户数据库，不联网，也不启动服务器。它比当前导入入口检查更严格，目的是提前发现丢课与时间错位；它不会替你证明学校数据源正确，也不检查未知附加字段是否含个人信息。

为新适配增加自己的纯解析测试，至少覆盖：

- 普通课程、同一课程多个星期或大节、实验分组与多行课名。
- 全周、单周、双周、离散周、后半学期课程、跨年校历。
- 空教师或教室、不同周次换教室、重复条目、无固定上课时间。
- 返回登录页、空响应、缺字段、非法星期/周次/时间、日期或作息缺失；错误不能变成“成功导出空课表”。
- 若使用请求，验证从不同页面目录进入时地址仍正确；测试中替换网络函数，不能请求真实教务网站。

最后由有权访问该系统的本人做实测：登录学校课表页面，确认按钮位置和权限；导出后逐项对照至少第 1 周、一个单周、一个双周和学期后段，核对课名、实际日期、起止时间、地点与总课程数；在自己的本地 DDL Killer 导入，分别查看日历和断网后的已缓存课表。如果有临时补课或调休，也要专门核对。恢复网络前不要连接维护者的生产数据库。

本地环境和通用测试说明见 [自部署](self-hosting.md) 与 [CI](ci.md)。修改学校脚本时，也运行对应的已有回归命令；仅完成虚构输入测试时，贡献说明应如实写“尚未在本人教务页面实测”。

## 把适配贡献回来

按 [参与指南](../CONTRIBUTING.md) 提交 Issue 或 PR。仓库公开后可以在 GitHub 讨论；当前使用者也可以通过应用内反馈提交学校需求。贡献材料建议包含：

1. 学校、校区、培养类型、教务系统名称或版本，以及适配覆盖与不支持的情况。不要附学号或账号。
2. 数据取得方式：官方文件转换，或本人页面/正常查询；说明对应的使用规则、最小权限、请求次数与频率，不需要提供登录材料。
3. 适配脚本与简短使用教程，包括浏览器/脚本管理器要求、入口、学期和作息确认、常见失败与卸载方式。
4. **重新编造的输入夹具**和对应预期 JSON，保留页面/字段结构与困难情况，课程、教师、教室、标识和日期均用示例值；不是只给原始文件打码。
5. 离线解析测试、运行命令及结果；本人实测的浏览器、日期、覆盖场景和剩余限制。截图只保留必要区域，清除姓名、学号、成绩、校内私人链接等信息。
6. 文件来源与许可证。你应有权提交代码和材料；不要把教务平台的专有脚本、整站页面或未获许可的素材搬入仓库。

通常学校脚本放在 `app/web/userscript/<school>-kebiao-export.user.js`，测试放在 `app/tool/`；具体命名与发布地址由维护者审阅后确定。加入新的学校帮助页与应用内支持文案，应在实测范围明确后一起处理。发现漏洞按 [安全说明](../SECURITY.md) 私下报告，不在公开 PR 放可利用细节或凭据。

你的贡献可以先从一个小范围开始：一所学校、一个校区、一种学期课表，准确说明边界、能离线验证，再逐步扩大覆盖。可复用的重点是数据归一化、日期与时间验证，以及由用户控制的导入流程。
